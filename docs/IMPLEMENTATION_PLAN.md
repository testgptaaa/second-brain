## Принцип выполнения

Весь основной объём из [ТЗ](SPECIFICATION.md) сохраняется. Этапы задают порядок получения проверяемых результатов. Завершение одного удачного сценария не означает завершение проекта. Точные даты и трудоёмкость определяются после проверки оборудования и технических ограничений; отсутствие точного дедлайна не заменяется предположением, что времени мало.

Независимые человеческие задачи могут выполняться одновременно после согласования ответственности; этот план не запускает дополнительных AI-агентов.

## Контрольные наборы

- Документы: PDF с текстом и скан, DOCX, таблица с несколькими листами, CSV, текстовая заметка; все на русском с английскими элементами.
- Экран: светлая и тёмная темы, мелкий шрифт, масштабирование, два монитора, всплывающее окно, смена активного приложения во время захвата.
- История: повторные посещения одной страницы, граница выбранного периода, повторный импорт, исключённый домен, удалённая локальная запись.
- Память: правильный источник числа, одинаковые числа в несвязанных документах, изменённый срок, вопрос без ответа, исправленная пользователем задача.
- Внешние правки: правка при работающем и закрытом приложении, атомарное сохранение, конфликт с автоматической записью, переименование, ошибочный YAML, внешнее удаление, массовое изменение, конфликтная копия sync-клиента.
- Интеграции: перенос и отмена встречи, повторяющаяся встреча, отозванное разрешение, изменение заметки Apple, недоступный файл и несохранённый документ.
- Сбои: 401/403/429/5xx модели, тайм-аут, отключение сети, невалидный ответ, нехватка места, остановка процесса между записью файла и базы.

Юнит-тесты нужны для политик доступа, границ времени, дедупликации, обработки ответа и удаления. Интеграционные тесты проверяют транзакции, очередь, индексы и протоколы. Реальные внешние подключения и системные разрешения проверяются отдельно; моки не заменяют их успешное прохождение.

## Проверка интерфейса и платформ

Для веб-интерфейса используется глобальный MCP chromeDevTools с отдельным Chrome, включая навигацию, консоль, сеть и разные размеры окна. Не запускать общий Chrome вручную и не использовать общий порт отладки. Если сервер недоступен, записать точную ошибку и невыполненные проверки. Браузерная проверка не доказывает работу меню/трея, системных разрешений, native bridge и упаковки: это отдельные проверки на macOS и Windows.

Предлагаемые размеры окна: 1440×900 и 1024×768; уменьшение до 800×600 проверяет отсутствие потери доступа к паузе и настройкам. Это десктопный продукт; мобильное приложение в согласованный объём не входит.

## Сценарий защиты

Офисный сотрудник открывает задачу Битрикса, получает уточнение в рабочем чате, сверяется с таблицей и страницей в браузере. Помощник связывает источники. После переключения на другое дело пользователь спрашивает, где остановился и откуда взял число; ответ открывает доказательства. Из уточнения предлагается задача, а перед встречей из календаря появляется справка. Затем показываются исключённый источник, пауза, режим обработки и журнал фактической отправки.

Краткий основной показ можно дополнить подготовленными случаями для всех восьми подсказок. Записанный резервный показ маркируется как запись; подмена live-интеграции симуляцией не выдаётся за рабочее подключение. Маскировка картинки не показывается и не обещается как готовая до E10.

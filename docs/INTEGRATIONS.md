# Подключение источников

Дата: 2026-10-25
Статус: изучена документация через Exa; живые подключения и права доступа не проверялись. Матрица задаёт план технической проверки, а не перечень уже работающих интеграций.

## Уровни доступа

Уровень 1 — разрешённый снимок активного окна. Уровень 2 — доступный текст интерфейса или страницы. Уровень 3 — разрешённый файл либо целевой импорт через API. Наличие одного уровня не доказывает наличие остальных. Статусы в интерфейсе: доступно, требуется разрешение, ограничено, не поддерживается, ошибка.

| Источник | Предлагаемый способ | Что проверяем до реализации |
| --- | --- | --- |
| macOS: окна | NSWorkspace для приложения, Accessibility для текста, ScreenCaptureKit для снимка | Системные разрешения, идентификация окна, отказ/отзыв доступа, Retina и несколько мониторов; API-обёртка и версия ОС |
| Windows: окна | Win32 для активного окна, UI Automation для текста, Windows.Graphics.Capture для снимка | Упакованный helper, DPI, несколько мониторов, закрытые/повышенные окна, запрет доступа и переключение фокуса |
| Chrome и Edge | Расширение: активная вкладка, content script, history; Native Messaging | Разрешения сайтов, установка расширения и моста, отдельные посещения, страницы с динамическим содержимым |
| Яндекс Браузер, Opera, Brave | Адаптация Chromium-расширения | Установка и совместимость каждого браузера отдельно; родство с Chromium не считается проверкой |
| Firefox | WebExtension и Native Messaging | Отличия manifest и фонового процесса; импорт истории, разрешения и связь с приложением |
| Safari на macOS | Safari Web Extension и нативный мост; отдельный путь импорта истории при отсутствии нужного API | Упаковка расширения, разрешения сайтов, доступность history в целевой версии; fallback через разрешённый экспорт или согласованную копию истории проверяется отдельно |
| Google Docs и Битрикс | Браузерный адаптер плюс экран/OCR | Canvas и виртуализированный текст, iframe, навигация без перезагрузки; прямой API Битрикса не требуется |
| Telegram и WhatsApp | Текст активного разрешённого окна через системный адаптер, OCR при необходимости | Реальная доступность текста и идентификатора чата; нет обещания загрузить всю переписку или непрочитанное |
| Word и Excel | Текст интерфейса, подтверждённый путь документа и локальный разбор | Несохранённые изменения, разрешение файла, таблицы/листы; COM или AppleScript только после проверки конкретной версии |
| PDF, DOCX, XLSX, CSV, TXT, Markdown | Извлечение текста и структуры из разрешённого файла | Скан против текстового PDF, Unstructured local, таблицы, кодировки, лимит размера, недоступный/изменившийся файл |
| Apple Notes на macOS | Прочитать доступный scripting dictionary, затем адаптер только чтения выбранных папок | Automation permission, HTML body, вложения и закрытые заметки, стабильный идентификатор; не обходить закрытие |
| Google Календарь | OAuth для desktop-приложения и Calendar API | Реальный OAuth, scopes только чтения, выбранные календари, повторения, отмены, часовые пояса и отключение аккаунта |

Все браузеры остаются направлением охвата; для каждого нового браузера нужен адаптер и отдельная запись о проверке. Экран неизвестного браузера не является полноценной поддержкой его истории и исключений сайтов. При невозможности идентифицировать сайт содержимое пропускается, если действуют ограничения сайтов. Для Safari отсутствие подтверждённого способа импорта — открытый риск, не повод незаметно заменить историю списком новых посещений.

## Особенности браузеров

Content script извлекает разрешённый видимый текст и сведения об источнике, но не получает универсальный доступ к canvas, закрытым shadow roots или всем iframe. История требует отдельного разрешения. Для импорта нужно перечислять visits и фильтровать их по времени, а не ограничиваться lastVisitTime страницы. Оригинальная история браузера не изменяется. Служебные страницы и приватные окна исключаются в предлагаемом контракте.

Доступные вкладки не означают, что пользователь прочитал их содержимое. События посещения, наблюдение активной страницы и загрузка файла имеют разные типы. Маскировка изображений отсутствует в основном объёме, но исключения сайтов действуют до захвата.

## Google Календарь

Предлагаются `calendar.events.readonly` и, при выборе календарей из списка, `calendar.calendarlist.readonly`. Не запрашивать права записи для текущего объёма. OAuth-проект и тестовые пользователи подготавливаются командой; готовый base URL модели не заменяет Google OAuth.

Читать события с пагинацией, сохранять syncToken и обрабатывать изменения и отмены. При потере валидности токена выполнять полную повторную синхронизацию по правилам API без дублирования. Набор параметров инкрементальной синхронизации ограничен API; временное окно интерфейса не должно приводить к пропуску изменений. Отключение интеграции останавливает новые запросы и предлагает отдельно удалить импортированные данные.

## Apple Notes

Документация Apple подтверждает общий механизм scripting dictionary, но состав и поведение Notes надо проверить локально на целевой версии. На этапе исследования пользовательские заметки не читались. Первую проверку проводить на специально созданной тестовой папке. Не обещать чтение закрытых заметок и полное извлечение вложений без доказательства. Windows-версия приложения сохраняет собственные заметки; автоматическое подключение iCloud Notes через браузер в основной объём не добавляется.

# OCR, модели и обезличивание

Дата: 2026-10-25
Статус: исследование первичных источников через Exa; компоненты не установлены и не протестированы. Рекомендации не являются окончательным выбором.

## Принятые направления

1. Изображение: отправлять разрешённый снимок модели с поддержкой картинок; до заключительного этапа без маскировки изображения.
2. Текст: получать доступный текст напрямую или локальным OCR, при выбранной настройке обезличивать его и передавать текстовой модели. Снимок в этом варианте не требуется прикладывать к запросу.
3. Локальная текстовая модель: пользователь запускает LM Studio, приложение подключается по API. Достаточно описать эту возможность, собственный запуск моделей не нужен.

Режим без маскировки явно включён в требования. Маскировка текста, маскировка изображения и место запуска модели — разные настройки. Локальный OCR с последующим запросом облачной модели не является полностью локальной обработкой.

## LM Studio

[Официальная документация](https://lmstudio.ai/docs/developer/openai-compat) описывает OpenAI-совместимые endpoints и base URL `http://localhost:1234/v1`, где 1234 — пример порта. В запросе указывается идентификатор загруженной модели. [Авторизация](https://lmstudio.ai/docs/developer/core/authentication) поддерживает API-токены; по документации она по умолчанию выключена и включается в настройках сервера. Текстовая модель не становится мультимодальной из-за наличия совместимого API. Для поиска по смыслу отдельно потребуется подходящая модель векторизации.

## Локальный OCR

| Кандидат | Подтверждено в документации | Рекомендация |
| --- | --- | --- |
| PaddleOCR PP-OCRv5 | `eslav_PP-OCRv5_mobile_rec` поддерживает русский, белорусский, украинский и английский; есть более широкий `cyrillic_PP-OCRv5_mobile_rec` | Первый кандидат для сравнения на офисных экранах; распознавателю нужен также этап обнаружения областей текста |
| Tesseract | Есть языковые данные `rus` и `eng`, варианты tessdata_fast и tessdata_best, вывод TSV/hOCR с координатами и уверенностью | Базовый вариант для сравнения и совместимости с Presidio Image Redactor |
| EasyOCR | Локальная обработка, CPU-режим, кириллица; возвращает области текста, текст и уверенность | Альтернатива для сравнительной проверки; пакет использует PyTorch |

Источники: [PaddleOCR и языки моделей](https://www.paddleocr.ai/latest/en/version3.x/algorithm/PP-OCRv5/PP-OCRv5_multi_languages.html), [Tesseract: языки](https://tesseract-ocr.github.io/tessdoc/Data-Files-in-different-versions.html), [Tesseract: TSV/hOCR](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html), [EasyOCR](https://github.com/JaidedAI/EasyOCR).

Выбор требует сравнения на русско-английских снимках браузера, чата, таблицы и документа: мелкий шрифт, тёмная тема, масштабирование, числа и порядок чтения. Измерять ошибки, задержку и расход памяти на обеих ОС. Опубликованные результаты моделей на чужих наборах не подтверждают качество на наших экранах. Модели скачиваются заранее для работы без сети.

## Пример пользователя с Unstructured

UnstructuredLoader загружает и разбирает PDF; `hi_res` включает анализ расположения элементов документа, это не название отдельной текстовой модели. OCR зависит от установленного движка и языковых данных. `RecursiveCharacterTextSplitter` разбивает результат на фрагменты; в приведённой настройке размеры 1000 и 200 относятся к символам по стандартной функции длины, а не к токенам. Кэш сохраняет результат обработки. Это подготовка данных для RAG, но ещё не полный поиск: нужны индекс, извлечение релевантных фрагментов и ответ с источниками.

Для документов Unstructured — подходящий кандидат; для периодического чтения экрана предлагается прямой OCR без обязательного полного разбора структуры PDF. Документы с доступным текстовым слоем можно читать без OCR. Для локального Unstructured нужны локальные зависимости, а не только клиент серверного API; явно проверять `partition_via_api=False` в выбранной версии и отсутствие отправок наружу.

Код ChunkManager не предоставлен, поэтому корректность кэша не проверена. При реализации учитывать хеш содержимого, настройки разбиения, язык и версию обработчика. Предпочтителен JSON для переносимых данных; pickle допустим только для доверенного собственного кэша. Сохранять страницу, источник и связь фрагментов; очистку текста применять до записи очищенного индекса, если этот режим включён.

Источники: [LangChain UnstructuredLoader](https://docs.langchain.com/oss/python/integrations/document_loaders/unstructured_file), [Unstructured partitioning](https://docs.unstructured.io/open-source/core-functionality/partitioning).

| [Natasha](https://github.com/natasha/natasha) | Русские имена, организации и места; работа на CPU, MIT | Это компонент распознавания сущностей, а не готовое полное обезличивание; модели ориентированы на новости |
| [Kefis89/Anonimyzer](https://github.com/Kefis89/Anonimyzer) | Готовый пример русского обезличивания: правила, Natasha, Presidio и необязательная LM Studio; MIT | Небольшой проект, требуется аудит; заявлено молчаливое отключение недоступных детекторов, что нельзя незаметно переносить в наш режим очистки |

Предварительная рекомендация: Presidio с русской языковой моделью и правилами телефонов, почты, ИНН, СНИЛС и паспортов. Natasha — альтернативный или дополнительный распознаватель после проверки. Не считать замену имён гарантией полной анонимности: контекст может оставаться идентифицирующим. Стабильные обозначения вроде «Человек 1» помогут связям в памяти, но правила соответствий и их хранение ещё не выбраны.

## NeuralDeep PII Guard

Веб-страница [docs#guardrails](https://neuraldeep.ru/docs#guardrails) через Exa вернула только оболочку. Содержимое нужного раздела получено через Exa из официального [llms-full.txt](https://neuraldeep.ru/llms-full.txt), найденного по [llms.txt](https://neuraldeep.ru/llms.txt). Прямой curl из среды завершился `curl: (6) Could not resolve host: neuraldeep.ru`; это не проверка API.

По документации провайдера:

- `POST /v1/pii/anonymize` принимает text или texts, возвращает обезличенный текст и mapping; `POST /v1/pii/deanonymize` восстанавливает данные из mapping.
- Заявлены 25 типов, включая имена, телефоны, почту, документы, банковские реквизиты и токены; используются ruBERT и правила.
- Можно включить PII Guard на ключе: обработка чат-запроса происходит перед передачей модели, ответ восстанавливается перед возвратом клиенту.
- Щит не обрабатывает картинки, embeddings, rerank и аудио.
- Обработка происходит на сервере NeuralDeep. Исходный текст выходит с устройства и доступен этому сервису, даже если следующая модель получает заменённые данные.
- Провайдер заявляет отсутствие хранения текста и удаление mapping на своей стороне после ответа. Это утверждения документации, а не результат нашей проверки.

NeuralDeep можно предложить как отдельный серверный вариант очистки текста. Он не заменяет локальное обезличивание, если цель — не передавать исходные данные за пределы компьютера. В полностью локальном режиме не используется.

## Маскировка изображений — самый последний этап

[Presidio Image Redactor](https://github.com/microsoft/presidio/tree/main/presidio-image-redactor) показывает готовый подход: Tesseract извлекает текст с координатами, детектор находит чувствительные фрагменты, области закрашиваются. Это маскировка текста на изображении, а не универсальное удаление лиц, фотографий, QR-кодов и всех возможных секретов. Русская конфигурация и качество на наших снимках требуют проверки.

По последнему решению пользователя эту функцию откладываем в самый конец. До её появления изображения отправляются без маскировки, даже если сопутствующий текст очищен. В настройках и журнале эти состояния должны различаться.

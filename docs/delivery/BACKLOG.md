# Исполнимые задачи M1

Источник: [ревью](REVIEW.md). Объём: [MILESTONES](MILESTONES.md). Общий статус M1: **IMPLEMENTED / MAC_ACCEPTANCE_PENDING**. Реализация SB-01–SB-13 и облачные проверки отражены в [итоговом отчёте](reports/2026-10-25-M1-implementation.md). SB-14 — **BLOCKED** до прогона на реальном Mac; это не ошибка Linux-настройки. M1 не считается принятым. Исторический [первый проход](reports/2026-10-25-M1-progress.md) сохранён как журнал, его список «остаётся» заменён итоговым отчётом.

Каждая задача выполняется отдельной поставкой. Общий Definition of Done: выполнены все критерии карточки; добавлен тест на исходную поломку; пройдены затронутые проверки и базовые pytest/build/typecheck; выполнено ревью diff; есть отчёт по шаблону TESTING с командами и результатами. Mock, ручной прогон и реальная интеграция маркируются отдельно. BLOCKED не равен DONE. Перед работой читать актуальный код, а не полагаться на номера строк аудита.

## SB-01 — Воспроизводимая база разработки (P1)

Зависимости: нет. Файлы: desktop/package.json, tsconfig*, README, docs/IMPLEMENTATION_PLAN; новая CI-конфигурация при отсутствии существующей.

Работа: добавить явные команды typecheck и verify; корректно подключить vite/client для CSS; выбрать и зафиксировать поддерживаемые Python/Node; описать раздельный запуск web-demo и Electron. Привести статусы документации к фактическим данным; сохранить старую карту E00–E10. Не обновлять все зависимости одновременно. Уточнить установку бинарника Electron с учётом npm lifecycle scripts; не включать посторонние install scripts глобально.

Приёмка: чистый npm ci не меняет lockfile; стандартный typecheck без специальных CLI-флагов проходит; renderer/Electron собираются; pytest выполняет существующие 11 тестов. CI запускает эти три проверки и не называет сборку GUI-тестом.

Проверки: повторить установку и verify в checkout с сохранением изменений; описать, что происходит при отсутствующем Electron binary. AC-01.

## SB-02 — Структурированные логи и диагностика (P1)

Зависит от SB-01. Файлы: core/src/main.py, ipc/handler.py, watcher/observer.py, desktop/electron/*, новый модуль logging, экран диагностики в SettingsScreen.

Работа: единая схема события `timestamp` (UTC ISO 8601), `level`, `component`, `event`, `session_id`, `request_id`, `duration_ms`, `error_code`; traceback только в диагностическом журнале. Python stdout оставить исключительно JSON-протоколу; operational logs — stderr/ротация файлов. Логи Electron хранить в userData/logs, Python — в согласованном каталоге runtime, не среди индексируемых документов. Начальная политика: 5 файлов × 5 MiB на процесс; уровень INFO, DEBUG включается явно. Журнал фактической отправки модели хранится отдельно.

Приёмка: пользователь видит состояние ядра, последнюю ошибку и способ открыть журнал; один request_id связывает UI/main/Python; неверная команда и ошибка диска оставляют полезный trace. Ключи, Authorization, тексты заметок, OCR, скриншоты и query не попадают в operational logs. Ошибка записи журнала не валит приложение и имеет ограниченный stderr fallback.

Проверки: перехват stdout и JSON parse каждой строки; синтетические secret markers отсутствуют во всех журналах; проверка ротации; readonly log directory; исключение watcher не теряется молча. AC-03/11.

## SB-03 — TLS и корректное хранение настроек/секретов (P0)

Зависит от SB-01/02. Файлы: gateway/client.py, ipc/handler.py, SettingsScreen, ModelConfig types; macOS Keychain adapter и тестовый fake adapter.

Работа: вернуть стандартную TLS-проверку во всех HTTP-клиентах; при необходимости поддержать доверенный CA через документированную настройку без verify=false. Убрать секреты из read DTO: возвращать только признаки наличия. Update DTO различает «оставить», «заменить», «удалить»; маска никогда не credential. Для Mac использовать Keychain; существующие SQLite credentials мигрировать только после успешной записи и проверки чтения из Keychain; при отказе оставить возможность повторить, не заявлять успех и не выводить значение. Зафиксировать обработку старых копий SQLite/backups: удаление строки не является доказательством физического стирания.

Приёмка: изменение модели/URL не меняет ключ; явное удаление удаляет binding; перезапуск сохраняет настройки; UI не содержит реальных ключей после чтения; недоступный Keychain виден как ошибка. Самоподписанный недоверенный TLS отклоняется, тестовый доверенный CA принимается.

Проверки: воспроизведение R03 с синтетическим ключом до/после; mock HTTP для 401/429/5xx/timeout/invalid JSON; интеграция Keychain на Mac в отдельном тестовом service namespace с очисткой. AC-04.

## SB-04 — Наблюдение только после согласия (P0)

Зависит от SB-02. Файлы: policy.py, ipc/handler.py, electron/main.ts, Sidebar/SettingsScreen.

Работа: отдельное persisted состояние consent, по умолчанию false; pause не подменяет согласие. На новой памяти timer не запускает захват и внешнюю отправку. UI/tray используют подтверждённое состояние Python, а не собственный несогласованный флаг. Для M1 capture показывается как ограниченная/непринятая возможность, безопасно выключенная; полный adapter acceptance — M2.

Приёмка: fresh install не снимает экран, не создаёт observation и не отправляет запросы; перезапуск/отказ разрешений не включают сбор; pause/resume отражаются одинаково в UI и tray. Запрет действует в самом backend, а не только в кнопке.

Проверки: spies capturer/gateway с нулём вызовов до consent; отказ/отзыв согласия; перезапуск с pause; Mac ручная проверка отсутствия захвата. AC-05.

## SB-05 — Устойчивый жизненный цикл IPC (P1)

Зависит от SB-02/04. Файлы: pythonBridge.ts, main.ts, main.py, handler.py.

Работа: startup handshake с timeout; обработка spawn error, exit, stdin failure; request timeout и очистка pending; корректное завершение. Стартовые лимиты: startup 15 s, локальный RPC 10 s, модель 45 s. Долгие LLM/OCR операции не блокируют pause/health; реализовать ограниченную очередь/отдельный worker и безопасное завершение. Все записи протокола из потоков сериализуются. UI получает состояния starting/ready/unavailable; повтор запроса на запись не делается автоматически.

Приёмка: недоступный Python не оставляет вечный spinner; зависший запрос отклоняется и удаляется из pending; crash завершает все запросы; поздний ответ не портит новый запрос; pause отвечает при зависшей модели. На Mac pause при заблокированном model worker завершается не позже 1 s в тестовом прогоне.

Проверки: fake child process + настоящий subprocess; malformed JSON, missing executable, delayed readiness, abrupt exit, late response, shutdown с pending; polling с deadline, без бесконечного sleep. AC-03.

## SB-06 — Целостность памяти и контракт CRUD/query (P1)

Зависит от SB-01/02. Файлы: memory/storage.py, index/indexer.py, watcher/observer.py, ipc/handler.py, memory/models.py.

Работа: явные list/get/update/delete notes/tasks и list/get сохранённых sources; валидируемые DTO; patch не сбрасывает пропущенные поля и отличает null от отсутствия. Поиск заметки по ID не зависит от сегодняшней даты; created_at неизменен. Стабильные ID без коллизий в одной миллисекунде. Удаление согласует файл, FTS, tasks и events; watcher учитывает delete/move; полный sync убирает stale rows, сохраняя settings/conflicts. Решить повторное выполнение и сбой между file/index записью. Пути/ID не допускают выхода за memory root, в том числе через symlink. Конфликт возвращает типизированный результат без перезаписи версий.

Приёмка: update вчерашней заметки оставляет один ID, прежние путь/created_at; все изменения после restart читаются; удалённый документ не находится ни сразу, ни после rebuild; rebuild идемпотентен и не затирает настройки. Невалидные статус/дата/limit/sort отклоняются явно. Удаление UI требует подтверждения; backend корректно отвечает на повторный delete.

Проверки: R06 регрессия, external rename/delete/atomic save, сохранение при конфликте, сбой write/index, path traversal, одинаковые timestamps, patch due_date=null без смены status. AC-06/07/10.

## SB-12 — Единые сортировки, фильтры и страницы (P1)

Зависит от SB-06/08–11. Файлы: indexer/query DTO, общие sort utilities, все списки.

Контракт: сортировки применяются ко всему набору **до** пагинации; SQL ORDER BY строится только по allowlist. Tie-break — id ASC, даты/instant сравниваются как даты, названия — согласованный locale-aware ru порядок. Невалидные даты не ломают список, идут после валидных. Выбор фильтров/сортировки переживает смену вкладки; при смене фильтра страница сбрасывается.

| Экран | По умолчанию | Доступные варианты и фильтры |
| --- | --- | --- |
| Задачи | активные, due ASC null last, created DESC, id ASC; внутри kanban те же ключи | срок ↑↓, создание ↑↓, название А–Я/Я–А; status, overdue, due range |
| Заметки | updated DESC, id ASC | изменение/создание ↑↓, название ↑↓; title query, tags |
| Файлы | captured DESC, id ASC | дата ↑↓, название ↑↓, тип; query, type, date range |
| История | день DESC; внутри дня created DESC, id ASC | день ↑↓, событие ↑↓; date range, kind |
| Поиск | BM25 ASC, id ASC | релевантность, updated DESC; doc_type, date range |

Приёмка: сортировка глобальна, детерминирована и не мутирует исходный массив; null due last в обоих направлениях; active default явно указан и cancelled/done доступны фильтром. Сохранённая комбинация несовместимых фильтров показывает empty + reset.

Проверки: фиксированный fixture TESTING; одинаковые даты/названия, null, кириллица/латиница, 51 запись на страницах по 20, двойное переключение направления, фильтр + сортировка + restart. AC-09.
